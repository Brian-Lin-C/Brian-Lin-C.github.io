计算机网络（二）数据传输与封装

在上一篇中我们了解了网络的分层模型。本篇将深入探讨数据在各层之间是如何传递的——封装与解封装机制。理解这一过程是掌握网络通信本质的关键。

一、什么是封装与解封装

1.1 现实世界的比喻

想象你要寄一个礼物给朋友：

每一层都加上自己的”包装”（头部信息），收件人收到后逐层”拆开”，最终拿到礼物。

1.2 技术定义

概念 定义 方向
封装（Encapsulation） 上层数据到达下层时，添加该层的头部（和尾部）信息 发送方，从上到下
解封装（Decapsulation） 下层数据到达上层时，移除该层的头部（和尾部）信息 接收方，从下到上

提醒自己：

  • 封装就像”穿衣服”，每层都加一层包装
  • 解封装就像”脱衣服”，逐层剥离头部信息
  • 对等层之间看到的是相同的头部信息（逻辑上的直接通信）

二、PDU：协议数据单元

2.1 PDU 的概念

PDU（Protocol Data Unit，协议数据单元） 是指对等层之间交换的数据单位。每层都有自己的 PDU 名称：

OSI 层次 PDU 名称 说明
应用层 数据（Data/Message） 用户实际发送的数据
传输层 段（Segment） TCP 协议的数据单元
传输层 数据报（Datagram） UDP 协议的数据单元
网络层 包/分组（Packet） IP 协议的数据单元
数据链路层 帧（Frame） 以太网等链路层的数据单元
物理层 比特（Bit） 0 和 1 的比特流

2.2 PDU 的组成

每个 PDU 都包含两个部分：

提醒自己：

  • 头部（Header）：该层的控制信息，用于对等层之间的通信
  • 有效载荷（Payload）：上层传递下来的数据，对本层来说是”黑盒”
  • 每层只关心自己的头部，不解析上层数据（除非特殊设计）

五、端到端通信 vs 逐跳通信

5.1 两种通信方式对比

5.2 各层的通信范围

层次 通信方式 说明
应用层 端到端 浏览器与 Web 服务器直接通信
传输层 端到端 TCP 连接建立在源和目的主机之间
网络层 逐跳 IP 包经过多个路由器转发
数据链路层 逐跳 每段链路独立传输（MAC 地址逐跳变化）
物理层 逐跳 信号在物理介质上逐段传输

5.3 实际例子：访问网站

提醒自己：

  • 端到端是逻辑概念，由传输层及以上实现
  • 逐跳是物理现实，由网络层及以下实现
  • TCP 的可靠传输是端到端的，中间路由器不参与重传
  • IP 的转发是逐跳的，每个路由器独立决策

六、MTU 与分片

6.1 MTU 的概念

MTU（Maximum Transmission Unit，最大传输单元） 是指数据链路层能够传输的最大帧数据部分（Payload）大小。

链路类型 默认 MTU 说明
以太网（Ethernet） 1500 字节 最常见的 MTU
PPPoE（宽带拨号） 1492 字节 1500 - 8（PPPoE 头部）
IEEE 802.3 1492 字节 早期以太网标准
Jumbo Frame（巨型帧） 9000 字节 数据中心高速网络
令牌环（Token Ring） 4464 字节 已淘汰

6.2 IP 分片

当 IP 包大小超过 MTU 时，需要进行分片：

提醒自己：

  • 分片在发送方或中间路由器进行，重组只在接收方进行
  • 任何一个分片丢失，整个 IP 包都需要重传
  • TCP 尽量避免分片（通过 MSS），UDP 无法避免

6.3 MSS：最大段大小

MSS（Maximum Segment Size） 是 TCP 层的概念，指 TCP 段的数据部分最大长度。

提醒自己：

  • MTU 是数据链路层的限制
  • MSS 是传输层的优化策略
  • TCP 三次握手时的 MSS 选项用于协商合适的段大小

八、常见面试问题

Q1：为什么有了 IP 地址还需要 MAC 地址？

答：

  • IP 地址是逻辑地址，用于全局寻址和路由选择
  • MAC 地址是物理地址，用于局域网内直接通信
  • 数据在局域网内传输时，需要知道下一跳的 MAC 地址才能封装成帧
  • IP 地址可以动态分配和变化，MAC 地址固定不变（通常）

Q2：TCP 是端到端的，这意味着什么？

答：

  • TCP 的连接建立、可靠传输、流量控制都在源和目的主机之间完成
  • 中间路由器只处理到 IP 层，不查看 TCP 头部
  • 如果数据丢失，由源主机重传，中间路由器不参与
  • 这保证了 TCP 的可靠性不依赖于中间网络的可靠性

Q3：发送 1MB 的文件，会封装成多少个帧？

答：

  • 假设 MTU = 1500，MSS = 1460
  • TCP 有效数据 = 1460 字节/段
  • 需要的 TCP 段数 = 1MB / 1460 ≈ 699 个段
  • 每个 TCP 段封装成一个 IP 包，再封装成一个帧
  • 所以大约需要 699 个帧

Q4：什么是路径 MTU 发现？

答：

  • 发送方设置 IP 头部的 DF（Don’t Fragment）标志为 1
  • 如果中间路由器的 MTU 较小，会返回 ICMP “需要分片但 DF 置位” 错误
  • 发送方收到后降低包大小重试
  • 最终找到路径上的最小 MTU，避免中途分片
